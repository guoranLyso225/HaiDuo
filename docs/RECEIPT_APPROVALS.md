# 普通入库审批

## 使用方法

1. 管理员在「系统设置 → 企业成员」创建仓库员工，再到「审批中心」设置成员职级为实习生（L1）。职责与职级分别设置；仅有高职级不代表拥有仓库操作权限。
2. 实习生登录，进入库存，选择仓库和 SKU，点击入库，在居中弹窗填写数量并确认。页面提示「入库申请已提交，库存尚未增加」。此时现存、预占、可用库存均不改变。
3. 另一名仓库主管（WAREHOUSE、L3）或管理员登录，进入「系统设置 → 审批中心 → 普通入库审批」。核对 SKU、仓库、数量及申请人，点击「批准入库」并填写意见。批准后才生成入库记录和审计事件，增加现存库存。
4. 信息错误可由申请人撤回，或由主管驳回（必须填写原因）；重新入库会创建新请求。申请24小时后审批会转为已过期，不增加库存。
5. 返回库存并刷新查看库存及流水。已生效入库若需纠错，仍使用「入库记录与冲销」，由独立人员批准整笔冲销，保留原始记录。

## 规则与边界

- 原 `POST /api/inventory/receipts` 根据服务端成员关系和职级决定 PENDING 或 APPLIED；旧客户端也受限制。L2及以上拥有 ADMIN/WAREHOUSE 职责时可直接入库。
- 待审请求不会因申请人升职或重试而直接生效。审批人须有仓库职责、职级至少L3且高于申请人，禁止自审；申请人职责被撤销时禁止批准。
- 数据库唯一键 `(tenant_id, request_key)` 固定一次请求的申请人、SKU、仓库及数量；不同参数复用键返回409，不同成员复用新账本中的键返回403。V27之前的入库无申请人字段，保留原幂等语义。
- 同事务写入入库记录、库存及审计/Outbox；重复审批不重复增加库存。库存达到整数上限则409，事务回滚且申请保持待审，可核对后重试或驳回。
- 列表最多200条；普通成员只看本人申请，主管查看当前企业申请。其他企业对象返回404。时间UTC存储、按用户时区展示。
- 这一步只增加普通入库审批；普通CSV导入、预占、发货、取消、商品创建等尚未全部接入职级审批。SKU编辑和纠错审批沿用各自既有规则。不得据此宣称全系统已统一审批。

## 接口

- `POST /api/inventory/receipts`：既有请求字段不变；返回 `{id, status, duplicate}`，不能只凭HTTP200判断已入库。
- `GET /api/receipt-approvals`：当前企业审批列表。
- `POST /api/receipt-approvals/{id}`：`{action: approve|reject|withdraw, comment}`，CSRF及服务端会话保护。
