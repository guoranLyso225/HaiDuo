# 释放预占与入库冲销

本批为安全纠错审批，不是删除历史。适用于本地演示及已授权的企业数据。

## 释放预占

1. 管理员、运营或仓库人员在订单页找到RESERVED订单，点击“申请释放预占”。
2. 单窗填写原因并提交。此时订单及库存不变。
3. 独立合格主管/管理员在系统设置→审批中心→订单与库存纠错审批查看仓库、当前单据明细及原因，批准或驳回。
4. 生效后整单返回NEW，现存不变，预占减少，可用恢复；旧预占与新增release流水保留。
5. 再次操作订单先刷新，可重新预占、发货。已发货或取消的订单不能走此流程。

它与取消订单不同：取消变成CANCELLED；释放只是撤回当前库存锁定，不撤销收入/费用，不修改付款状态。审批期间状态/预占轮次变化，申请变为STALE，不执行旧动作。

为了防止旧请求在新一轮预占中误执行，首次预占兼容原API；释放后再次POST reserve必须携带订单列表返回的inventory_revision，正文为`{"revision":2}`这样的当前轮次。过期或缺失轮次返回409，页面已自动传递。返回RESERVED的重复预占不会重复扣库存。

## 冲销入库

1. 库存页选择仓库，进入“入库记录与冲销”标签。
2. 找到误记入库记录，点击“申请冲销入库”，核对SKU、数量和仓库并填写原因。
3. 独立仓库主管或管理员在审批中心处理。管理员自己的申请也需要另一管理员，禁止自审。
4. 仅支持整笔冲销，审批时重新检查可用库存能否扣回全部数量。库存不足时返回409，业务全部回滚，申请仍待审批，可核对后重试、撤回或驳回。
5. 生效后原入库仍保留且标记已冲销，库存流水新增receipt_reverse负数记录。重复提交/批准不再次减少库存；针对同一入库的其他待处理申请将变为STALE。

冲销是库存账务纠错，不代表实物退货、不追溯采购批次消耗，也不改写历史订单采购成本。没有批次追踪时，仅以当前仓库可用库存作为自动执行边界，审批人必须核实真实业务；不能用它修正已发货事实或冒充退货验收。部分冲销、退货、调拨、盘点调整仍未实现。

## 权限

- RELEASE申请与审核职责：ADMIN、OPERATIONS、WAREHOUSE。
- RECEIPT_REVERSE申请与审核职责：ADMIN、WAREHOUSE。
- 所有职级申请均待审批；审核人至少L3且不低于申请人，关键纠错允许独立同级主管或管理员审核，禁止自审。
- 申请人和审核人当前角色、成员关系及职级会重新验证。普通成员仅看自己的申请，主管/管理员可查看本企业最近200条。
- 两个新纠错流程接入审批，不代表既有入库、取消、发货等其他写接口已实现通用审批。

审批中心显示当前单据明细供核对；历史结果以不可变原入库、反向记录、分轮次库存流水及申请记录联合追溯。该明细不是历史单据版本快照。

## 技术与接口

V25增加sales_order.inventory_revision、库存流水cycle、inventory_correction及receipt_reversal。原库存流水不删除。预占记录可从RELEASED重新进入RESERVED，每轮流水单独唯一。多SKU释放在一个数据库事务中执行，任何一行不一致整单回滚。

纠错审批事务锁申请、订单/原入库及相关库存；企业NO KEY UPDATE锁协调成员权限变更，同时允许其他业务外键KEY SHARE，避免不必要的锁等待。业务、审计与Outbox同事务。请求键绑定申请内容，重复请求返回原申请；数据库唯一约束限制每笔入库只冲销一次。

| 接口 | 用途 |
|---|---|
| GET /api/corrections | 企业内有权查看的纠错申请 |
| POST /api/corrections | kind、targetId、reason、requestKey；kind为RELEASE或RECEIPT_REVERSE |
| POST /api/corrections/{id} | action为approve/reject/withdraw，comment为意见，驳回必填 |
| GET /api/corrections/receipts?warehouseId=UUID | 管理员/仓库查询指定仓库最近200笔入库及冲销状态 |

拒绝或撤回不改库存，申请24小时到期；执行失败不伪报已生效。幂等键不是客户端租户凭据，租户始终由已验证会话成员关系确定。
