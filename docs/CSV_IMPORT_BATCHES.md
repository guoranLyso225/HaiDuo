# CSV预览、导入批次与撤销

本批支持先预览再确认、逐行报错、导入批次追溯，以及无后续业务的整批逻辑撤销。普通导入仍沿用ADMIN/OPERATIONS职责权限，尚未将所有实习生导入接入通用审批；批次撤销始终需要独立审核。

## 导入

1. 在订单页选择履约仓库，粘贴CSV或读取UTF-8 CSV文件。
2. 点击“导入CSV文本”，进入居中的预览窗口。此步不创建订单、费用、批次、审计或Outbox。
3. 查看预计新增、重复跳过、整单收入、汇率、SKU数量及当前采购成本；多SKU同单收入不累加。
4. 有错误时显示CSV行号和原因，整批不能确认。关闭窗口、修正原文本后重新预览。
5. 无错误点击“确认导入”。服务端重新校验，SKU版本/成本或已有订单变化会返回409，提示重新预览；不偷偷采用旧预览继续写入。
6. 成功提示新增和重复数量、批次编号；“CSV导入批次与撤销”折叠区可查看批次。

预览不是库存预占，也不保证未来仍有库存。确认只创建订单和成本/汇率快照，预占仍需单独执行。重复订单不会更新原金额或SKU。

同一次确认使用固定请求键，网络结果不明可在原预览重试，返回同一批次；修改内容需重新预览，不能复用同一请求键。CSV上限100000字符、500条数据行；暂不支持引号字段、字段内逗号。

## 批次详情与撤销

1. 展开CSV导入批次与撤销，找到批次，点击查看批次。
2. 详情只列本批真正新增的订单。重复跳过的历史订单不属于本批，不会被本批撤销。
3. 仅ACTIVE、有新增订单且所有新增单均无后续业务时，可申请撤销。
4. 填原因提交，业务数据此时不变。另一位合格运营主管或管理员在审批中心查看“CSV批次撤销”，批准或驳回；禁止自审，包括管理员自己申请。
5. 批准时锁定全批订单再次检查。任一单不符合即整批不执行，申请标为STALE。
6. 成功后批次标为ROLLED_BACK，相关订单标为CANCELLED并带import_voided。订单、明细、汇率和成本快照、原审计全部保留，新增撤销审计。

以下任一情况阻止撤销：非NEW、任何预占/释放或库存流水历史、费用（即使为0）、运单、付款/退款进展、实际贡献确认、平台同步或其他业务修改。释放预占退回NEW也不符合撤销条件。

没有新增订单的纯重复批次不能用于撤销旧单。撤销只适用于本功能上线后记录的CSV批次，旧订单和平台同步订单不能临时拼成一个可撤销批次。

## 历史与统计

这是逻辑撤销，不是删除。订单号仍被占用，再导入同一企业/店铺/订单号会跳过，不自动复活。若需重新处理，使用新的订单号并核对来源，不要直接改数据库。撤销订单不计入原有“非取消订单”看板和利润；历史详情和导出仍可追溯。撤销后禁止录入费用，平台同步不会自动改写该已撤销CSV订单。

## 接口及数据

- POST /api/orders/import/preview：csv、warehouseId；返回orders、errors、imported、duplicates、digest、canImport，不写业务数据。
- POST /api/orders/import：确认时增加previewDigest、requestKey（UUID）。历史客户端仍可不传，保留直接校验导入兼容，但每次实际导入都会记录批次。
- GET /api/order-imports：当前企业最近200批；GET /api/order-imports/{id}：详情和当前可撤销条件。
- POST /api/corrections：kind=CSV_ROLLBACK，targetId为批次ID；后续处理复用独立审批接口。

V26新增csv_import_batch、csv_import_order，按企业关联批次/订单/仓库，新增订单唯一归属一个批次；sales_order.import_voided保留撤销标记。request_key在企业内唯一并校验提交者及内容摘要，原始CSV不落库。确认锁SKU并重读成本版本；并发新增导致预期数量变化时，确认事务全部回滚。批次撤销锁全批订单，与原有费用/库存/发货行锁协调，不允许只撤销一部分。

导入与撤销操作由服务端认证成员关系确定企业，不信任客户端tenant_id；写接口保留CSRF和权限校验，金额以十进制字符串传输。预览摘要用于陈旧数据检测，不代替权限验证。
