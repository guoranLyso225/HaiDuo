# SKU编辑与分级审批

首批范围：SKU名称、当前成本、职级配置、审批中心。其他订单、库存、成员角色等写入尚未接入通用审批，不能宣称所有实习生业务操作都受审批控制。

## 职级

原有ADMIN/OPERATIONS/FINANCE/WAREHOUSE职责保留，职级独立；ADMIN固定L4，其他已有成员默认L2。

- L1实习：SKU修改需审批，不能自审；财务职责才可申请成本修改。
- L2员工：职责内SKU名称可直接修改；成本变更需独立审批。
- L3主管：在职责范围审批；成本需财务主管或管理员。关键成本允许另一同级财务主管审核。
- L4管理员：名称可直接修改；成本也需另一管理员批准，固定admin账号不豁免自审限制。

本批由管理员直接配置其他非管理员成员L1至L3并记录审计，职级配置本身暂未双人审批，成员角色仍按原流程管理。职级不会自动授予其他职责的权限。

## 演练

1. 管理员在系统设置→企业成员新建两个运营账号，例如intern01和lead01，密码遵守原规则。
2. 到系统设置→审批中心，分别设置为实习生和主管。管理员固定4，不通过该入口改自身职级。
3. 实习生登录同企业，商品行点击编辑SKU，修改名称并填原因。运营账号的成本只读，SKU编码本批只读。
4. 保存后提示已提交审批、尚未生效，商品原值保持不变。
5. 主管登录，在审批中心找到记录、查看前后差异、批准并填意见；只有显示已生效才改商品。驳回须填原因。
6. 申请人可以撤回待处理申请；已生效变更不能撤回，需新建修改申请。
7. 成本由财务/管理员申请，独立合格人员审核。已有订单成本/利润不变，后续新订单才使用新成本。

例：100USD×7.2、旧成本200，SKU成本改220后旧单未录费用贡献仍520；录运费50及平台费72后仍398。

## 状态和约束

PENDING待审批；APPLIED已生效；REJECTED驳回；WITHDRAWN撤回；STALE商品版本变化须重新提交；EXPIRED过期。申请24小时有效，在处理时标记过期，列表尚未处理的记录可能仍显示待审批。

后端重新验证申请人/审核人当前企业权限、职级和职责。禁止自审、跨企业、权限不足操作。企业行锁协调审批和成员角色/职级修改，SKU行锁及版本校验防覆盖。业务、审计和SKU_UPDATE Outbox同事务。重复请求键返回同一申请；重复/并发批准不重复执行。

V23新增member_grade、sku_approval、sku.version；V24新增request_key唯一约束、reviewed_at。

| POST /api/approvals | 保存名称或提交审批 |
