# 业务审批、详细编辑与纠错

本轮范围：补齐低职级业务写入审批；商品资料/编码/归档、订单明细/复制、库存盘点/部分冲销/实物退货、运单更正及历史；成员提级和角色调整的独立管理员审批。不是生产平台退款、承运商撤单或库存批次追踪系统。

## 一、职责和职级

职责仍为管理员、运营、仓库、财务，职级决定是否需要审批。管理员固定L4；普通成员默认L2，可设为L1或L3。

| 操作 | 生效规则 |
|---|---|
| 商品/SKU创建、订单CSV导入、预占/取消、发货、商品图片、店铺创建/映射/读取、知识导入/文案生成、物流模拟、同步配置、费用/贡献确认、普通编辑 | L1有对应职责时提交审批，由相应职责的L3或管理员批准；L2以上按原职责直接执行 |
| SKU名称和采购成本修改 | 沿用SKU审批：L1名称须审核；成本变更各级都需独立财务主管或管理员审核 |
| 普通入库 | 沿用普通入库审批：L1须审核，L2以上按仓库职责直接执行 |
| 释放预占、整笔冲销、CSV批次撤销 | 沿用纠错审批，各级均须独立审核 |
| 商品归档/恢复、SKU编码、盘点、部分冲销、实物退货验收 | 各级均须独立对应主管或管理员批准；L3可由另一同职责L3审核，L4须另一管理员 |
| 成员角色调整、职级上调 | 申请管理员不能自审，须另一位当前企业管理员批准。职级下调由管理员直接执行；不能修改自己的职级，管理员职级固定4 |
| 创建管理员账号 | 先创建普通运营身份，再创建ADMIN授予申请；独立管理员批准前没有管理员权限。普通员工创建沿用管理员直接创建流程 |

审批不能扩大业务职责：仓库人员不能借审批申请商品成本修改。企业A的管理员也不能查看或操作企业B的申请。只有一位管理员时，需通过企业受控初始化建立独立审批人；系统不会自动允许自审。

旧REST写接口已接入同一判定。`HTTP 200/201`可能表示申请创建成功，务必检查`status=PENDING`或`APPLIED`。登录、切换企业、读取/导出和AI问答不属于待审批业务修改；平台Webhook和后台权威同步按既有系统流程处理。连接凭据不放入通用审批正文。

## 二、如何提交和审批

1. 管理员进入「系统设置 → 企业成员」创建员工。成员过多可在「筛选成员账号」输入账号定位。
2. 进入「审批中心」，输入成员账号、选择职级并点「设置职级」。降低为实习生可直接执行；上调为主管会创建待审批申请。
3. 实习生按原页面进行创建、导入、预占或发货等操作。成功提示会明确说明「尚未生效」，业务数据和库存此时不改变。图片会先保存授权文件，批准前不会替换商品图片。
4. 合格主管或另一管理员登录，进入「审批中心 → 业务与权限审批」。点击「申请详情」，核对申请内容及提交时状态，再「批准申请」或「驳回申请」。驳回必须填写意见。
5. APPLIED代表业务与审批结果已在同一事务提交；库存不足、数量上限等执行失败会回滚业务，申请仍待审，供核对后重试或驳回。旧状态与当前状态不同显示STALE，不覆盖新数据。
6. 待审批申请24小时过期。申请人可撤回；驳回、撤回、过期后可「重新提交申请」。STALE应回原页面刷新后重新编辑/预览。重复审核或重试不会重复执行已经生效的申请。
7. 成员权限、职级、申请对象状态均在批准时重新验证。管理员本人提出的关键操作仍不能自审，使用本地快捷admin账号也没有例外。

## 三、商品详细编辑与整理

在商品行点击「编辑与纠错」：

- **编辑商品资料**：修改同一商品所有SKU共用的资料名称；各SKU名称继续用「编辑SKU」单独修改。列表分别显示商品资料名称与SKU名称。
- **修改SKU编码**：旧编码永久保留为当前企业同一SKU的别名，不能被其他SKU重新占用；UUID和店铺映射保持不变。CSV和平台按SKU回退映射支持旧别名；商品列表可按别名搜索。
- **归档或恢复商品**：归档后禁止新CSV导入、新增SKU及新预占，保留原订单、库存、图片及历史。已有预占仍可继续发货或取消。默认列表显示状态，方便恢复；不硬删记录。
- **修改历史**：查看编辑前状态、提交内容、原因、操作人及时间。更正已生效资料可再次编辑，版本冲突需刷新。

表单关闭前有未提交改动会确认是否放弃；弹窗居中，多字段在一个表单填写。

## 四、订单编辑、复制和运单更正

- NEW CSV订单：订单行「编辑与纠错 → 编辑订单明细」，调整仓库及完整SKU数量，可增加或移除SKU。原有SKU保留原采购成本快照，新加入SKU采用当前成本。收入及汇率值不在此入口变更。平台订单、已撤销批次、已预占/发货订单不允许在此改业务行。
- RESERVED：使用既有「申请释放预占」，批准后回NEW，再编辑或重新履约。
- CANCELLED CSV订单：「复制取消订单」填写新订单号。创建全新批次/订单，采用当前成本，继承收入与汇率值；旧单仍保持取消，不复活原编号。
- 物流页面：「编辑与纠错 → 更正运单」填写承运商、运单号和原因。使用独立编辑版本，旧表单返回409；不重做发货、不增加库存。物流轨迹事件版本独立保留。
- 利润页面「编辑与纠错 → 修改历史」可查看费用修改前后记录。实际贡献确认仍追加版本，旧确认不可改写。

## 五、盘点、部分冲销与退货

### 盘点

库存行「编辑与纠错 → 库存盘点」，填写实盘数量及原因。提交时的现存/预占快照固定；审批时任一变化都需重新核对。实盘不得低于预占，批准后记录正负调整流水，不直接篡改预占。

### 部分冲销

「库存 → 入库记录与冲销 → 编辑与纠错 → 部分冲销入库」，填写本次数量及原因。累计不得超过原入库，且仓库可用库存足够；批准后记负向流水。部分冲销后不能再整笔冲销，剩余数量继续使用部分冲销。该操作不是批次追踪或实物退货。

### 退货验收

已发货订单行「编辑与纠错 → 退货验收入库」，选择订单中的SKU，填写已经实物验收的数量与原因。一次处理一个SKU，可多次验收；累计不得超过该订单已发出的该SKU数量。独立审批通过后回原履约仓库，写正向流水，订单仍保留SHIPPED历史。

**这一步只记录实物回库**，不自动向平台退款、不撤销承运商运输、不修改支付/退款状态、不重算历史成本或实际利润确认。利润页面标明有退货需要人工核对退款及成本。多仓退货、换货、批次/序列号追踪及会计对账属于后续独立流程。

## 六、接口与数据

- `GET /api/workflows`，`POST /api/workflows/{id}`，`POST /api/workflows/{id}/resubmit`。
- `POST /api/business-edits`：白名单kind、targetId、version、requestKey、reason及操作专属字段。
- `GET /api/business-edits/{sku}`，`GET /api/business-edits/order-lines/{id}`，`GET /api/business-edits/history/{target}`。
- V28：business_request、business_history、business_adjustment、product_control、sku_alias。V29：shipment.edit_version。

申请固定保存白名单载荷及提交时状态，金额使用字符串。待审CSV仅含指定模板业务字段，不含客户地址；为审批会持久化该CSV载荷，与此前“原始CSV不落库”的批次实现有所不同。密码、平台令牌、密钥不进入通用申请。

审批执行采用固定命令分发，无任意URL、SQL或反射入口；内部执行上下文不接受客户端标记。审批状态、业务数据、审计和Outbox同事务。库存仍使用条件更新/行锁，不能部分成功。
