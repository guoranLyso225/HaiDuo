# 海舵 HaiDuo 中文使用手册

适用版本：当前仓库本地演示版。更新日期：2026-11-11。

本手册面向首次使用者，说明怎样启动、登录并完成一笔订单。功能说明已对照页面源码和接口；它不是新一轮测试通过报告，验收结果以实施记录为准。

## 1. 海舵用来做什么

海舵是面向跨境卖家的运营后台，用来集中管理店铺、商品、订单、仓库库存、物流和经营贡献利润。它不是消费者购物网站，也不是支付平台或会计核算软件。

一个企业拥有自己的成员和业务数据。登录后选择企业，后续操作属于当前企业。切换企业前请结束正在填写的表单并核对页面中的企业名称。

支持三种订单来源：手动CSV导入、固定MOCK样例、本地自建WooCommerce店铺。Shopify适配代码已有，但真实连接需要独立凭据和验收。Woo连接只读，海舵发货不会自动回写Woo运单或库存。

## 2. 启动与关闭

### Windows首次使用已有项目

1. 打开Docker Desktop，使用Linux容器引擎。
2. 打开PowerShell，进入项目目录。
3. 保留已有`.env`、`.demo-password`、`.woo.env`，不要用模板覆盖它们。新电脑才复制`.env.example`为`.env`，设置数据库、RabbitMQ和演示密码；本机HTTP使用`COOKIE_SECURE=false`。
4. 查看服务状态，再启动缺少的服务：

```powershell
cd D:\HaiDuo
docker compose --env-file .env -f infra/compose.yml ps
docker compose --env-file .env -f infra/compose.yml up -d --wait --wait-timeout 180
```

首次没有镜像或修改过源码时，使用以下命令构建并启动：

```powershell
docker compose --env-file .env -f infra/compose.yml up -d --build --wait --wait-timeout 180
```

`-d`表示后台运行。就绪后即可打开浏览器，不需要等待容器退出。首次构建需要下载依赖，网络失败应查看错误，不要反复重复启动。

| 地址 | 用途 |
|---|---|
| http://localhost:8088 | 海舵后台 |
| http://localhost:8090 | 本地Woo店铺，需单独启动 |
| http://localhost:8090/wp-admin/ | 本地Woo管理后台 |

只用CSV或MOCK时，不必启动Woo。需要Woo时执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File infra/start-woocommerce-link.ps1
```

此命令要求`.env`已有有效、持久的`TOKEN_ENCRYPTION_KEY`。密钥用于解密连接凭据，不能随意更换。单次`ExecutionPolicy Bypass`仅作用于该PowerShell进程。

### 关闭后保留数据

```powershell
docker compose --env-file .env -f infra/compose.yml stop
docker compose --env-file .woo.env -f infra/compose.woocommerce.yml --profile webhooks stop
```

第二条仅用于已安装Woo的环境。下次使用重新启动即可。不要用`down -v`作为日常关闭方法，它会删除项目数据卷。Docker中核心通常有前端、API、PostgreSQL、Redis、RabbitMQ五个容器；Woo联调另外需要店铺、MariaDB和cron三个容器。

### Linux/macOS

在项目根目录执行相同Compose命令。运行`.ps1`需先安装PowerShell 7，然后使用`pwsh -File infra/start-woocommerce-link.ps1`。本文Windows路径需换成自己的目录；不同宿主环境的实际验证范围见运行文档和实施记录。

## 3. 登录和角色

本地demo快捷管理员：账号 **admin**，固定密码 **1234**。每次demo启动重置，拥有两个示范企业的ADMIN最高企业权限；登录后仍须选择企业。仅供本地演示，非demo环境不会初始化该账号。已有容器须重建API后生效。


使用首次初始化时设置的演示密码。自动化演示环境通常保存在本机`.demo-password`；初始配置由`DEMO_PASSWORD`提供。数据库已有账号后，修改环境变量或重启不会自动修改账号密码。

| 账号 | 用途 |
|---|---|
| `demo1.admin` | 企业1管理员，首次体验建议使用 |
| `demo1.operations` | 企业1运营 |
| `demo1.warehouse` | 企业1仓库人员 |
| `demo1.finance` | 企业1财务 |
| `demo2.admin`等同类账号 | 企业2隔离演示 |

演示账号仅在demo环境初始化。具体允许的动作可由管理员在系统设置的角色权限页面查看；菜单可见不表示当前角色有写权限。遇到403先检查角色，跨企业对象可能返回404。

桌面使用侧栏导航，手机使用菜单抽屉。登录后先选择所属企业，再进入业务页面。

## 5. 第一次演练：从CSV到398元利润

建议全程使用`demo1.admin`，以免切换角色干扰学习。只操作演示数据。

### 第一步：检查店铺和商品

1. 店铺页确认有名为`mock`的模拟店铺；CSV的`store`必须与店铺名称完全一致。
2. 商品页搜索`DEMO-BAG`，确认采购成本为`200`元。
3. 也可以点击创建商品SKU，填写自己的唯一SKU编码、名称和成本。SKU编码使用英文字母、数字、下划线或短横线，不填中文。
4. 如果创建了自己的SKU，下面CSV也要使用该编码。

### 第二步：确认履约仓库有货

打开库存页，选择“默认仓库”，搜索`DEMO-BAG`。若可用不足1，点击该行“入库”，填写正整数，例如`10`。

库存三个数字的含义：

- **现存**：仓库账面尚未发出的数量。
- **预占**：已被订单锁定、尚未发出的数量。
- **可用**：现存减预占；新订单只能预占可用数量。

入库响应不确定时先刷新检查，使用原页面重试上一笔，不要另开多页重复登记。入库数量范围为1至1000000。

### 第三步：导入订单

打开订单页，选择“履约仓库”为默认仓库，把下面文本粘贴到CSV文本框，点击“导入CSV文本”。也可选取UTF-8编码的CSV文件，文件内容会进入文本框，再点击导入。

```csv
store,order_no,sku,quantity,net,currency,rate
mock,GUIDE-20261111-001,DEMO-BAG,1,100.00,USD,7.2
```

重复演练时换一个订单号，例如`GUIDE-20261111-002`。重复导入同一企业、同店铺、同订单号用于重试，不用于新增业务。

| 列 | 填写规则 |
|---|---|
| store | 当前企业已创建的店铺名称，示例为mock |
| order_no | 平台订单号，建议演练使用自己的唯一编号 |
| sku | 当前企业已有SKU编码 |
| quantity | 正整数数量 |
| net | 整单原币净收入；示例100美元，不是单价 |
| currency | 大写币种，例如USD或CNY |
| rate | 1单位原币折合人民币多少元；USD示例7.2，CNY填1 |

注意：页面初始示例可能写着“模拟店铺”和“请替换已有SKU”，必须改成真实已创建的名称及编码，不能直接照原样提交。文件上限100KB；不支持带引号字段、字段内逗号。金额不填人民币符号、千位逗号或科学计数法。

### 第四步：预占、查看详情和发货

1. 在“平台订单号”搜索框搜索刚导入的编号。
2. 点击订单号查看详情：原币收入、汇率快照、SKU、成本、费用、状态时间线。
3. `NEW`状态点击“预占”，成功后变成`RESERVED`。
4. 库存页刷新，应看到预占增加1，可用减少1，现存不变。
5. 回订单页点击“整单发货”，依次填写承运商和运单号。本地演练可填`LOCAL-MOCK`、`GUIDE-TRACK-001`，这不代表真实承运商发货。
6. 成功后订单变成`SHIPPED`；库存现存和预占各减少1，产生库存流水，物流页出现运单。

若演练取消，则在未发货订单行点击“取消”或“取消未预占”：已预占订单释放库存；取消不会增加现存。首版不支持复杂拆单、部分发货或通过取消撤销已发货订单。

### 第五步：查看398元预估贡献

进入利润页，找到该订单，点击“录入费用”：

1. 运费：金额`50`、币种`CNY`、汇率`1`，填写来源说明后保存。
2. 再次打开，平台费：金额`72`、币种`CNY`、汇率`1`，填写来源说明后保存。
3. 刷新，预估经营贡献应为`398.00 CNY`。

```text
100 USD × 7.2 − 200 CNY采购成本 − 50 CNY运费 − 72 CNY平台费 = 398 CNY
```

费用按类别覆盖保存，同类费用再次保存不是累加。若费用来自多笔账单，先核对类别合计。未录入费用按0估算；贡献不包含广告、工资、固定支出及税费，不等于会计净利润。汇率和成本采用订单历史快照，修改当前配置不会自动改写旧订单。

**CSV没有付款凭证，支付状态通常为UNKNOWN。** 发货不自动代表已付款。此路线可以查看预估贡献，但不能因此直接完成“人工确认实际贡献”。实际确认要求已付款、已发货、无退款，且明确录入运费和平台费（为0也要录入），由管理员或财务核对后填写说明；记录不可改写，调整须创建新版本。

## 6. 多SKU和多仓库

你已完成第五步时，保留398元示例，不需要重复操作旧订单。按照下面步骤练习第二笔订单：

1. 商品页点击创建商品SKU，填编码`GUIDE-SECOND`、名称“演练配件”、成本`20.00`。已有此编码则直接使用。
2. 库存页选择默认仓库，搜索`GUIDE-SECOND`，点击入库；在居中表单填10并确认。确认可用库存至少2。
3. 搜索`DEMO-BAG`，确认同一仓库可用至少1，不足时先入库。
4. 将下面CSV中的`MY-SECOND-SKU`换为`GUIDE-SECOND`，订单号换为尚未使用的`GUIDE-MULTI-20261115-001`。
5. 订单页选择同一仓库，一起粘贴两行CSV并导入；提示应为新增1单，不是2单。
6. 搜索订单号，点击详情核对两种SKU及数量1和2，关闭详情后预占。应整单进入RESERVED。
7. 点击整单发货，在同一个居中表单填写承运商`LOCAL-MOCK`和唯一运单号，点击确认。
8. 回库存查两个SKU的流水；利润中采购成本应为200+2×20=240，未录费用时预估贡献为150×7.2−240=840元。

WH-加13位时间戳的仓库来自历史自动化测试。订单和库存选择器默认折叠，勾选“显示历史测试仓库”可查看。它们可能有订单、库存及流水，折叠不会删除这些记录。

先创建第二个SKU并向同一履约仓库入库。整单每行重复同一个净收入、币种及汇率：

```csv
store,order_no,sku,quantity,net,currency,rate
mock,GUIDE-MULTI-001,DEMO-BAG,1,150.00,USD,7.2
mock,GUIDE-MULTI-001,MY-SECOND-SKU,2,150.00,USD,7.2
```

将`MY-SECOND-SKU`替换为已创建编码。整单收入仍为150美元，不是300美元。同一订单不能重复出现相同SKU，先合并数量。整单所有SKU都够货才会预占成功，不会只锁定一部分。

使用其他仓库时，先在系统管理入口创建仓库，再给该仓库入库，并在CSV导入前选择相同履约仓库。其他仓库有库存不代表当前订单仓库有货。

## 7. MOCK和Woo订单同步

建议先体验MOCK，再配置Woo：

1. 店铺页搜索mock，找到平台MOCK的一行并点击读取订单。
2. 到同步任务刷新，查看STORE_SYNC，再到订单搜索`MOCK-SYNC-001`。重复读取不会持续新增。
3. 要创建自己的店铺，先在名称输入框填写例如`我的练习店`，平台选模拟店铺，再点击创建店铺。名称不可为空、包含逗号或换行，也不能与当前企业已有店铺重复。
4. 对新店铺读取订单后，核对店铺名和订单号，不要把其他店铺的同编号订单混为一单。
5. Woo按下文启动后单独创建Woo类型店铺；配置连接、保存仓库汇率、读取订单、检查任务、检查业务订单，五步都要完成。

### 固定MOCK演示

在店铺页找到模拟店铺，点击“读取订单”，到同步任务页等待完成，再查`MOCK-SYNC-001`。它是固定样例，重复读取不意味着每次新增订单。

“已排队”只表示任务受理，不表示已经生成订单。任务完成后还需核对业务结果；没有来源订单也可能完成空同步。

### 本地Woo连接

1. 按第2节启动联调环境，打开海舵店铺页。已有已连接Woo店铺则使用它，不要重复绑定同一来源。
2. 新建时选择“WooCommerce（只读连接）”，填写店铺名称。
3. 打开“连接配置”，从本机`.woo-credentials.json`读取`consumerKey`、`consumerSecret`和`webhookSecret`，对应填写三项后点击“验证并连接WooCommerce”。不要上传凭据文件或截图分享密钥。
4. 填写同步履约仓库、币种`USD`、汇率`7.2`及“本地演示固定汇率”等来源，点击“保存同步配置”。这里7.2是演练值，不是实时汇率。
5. 关闭抽屉，点击“读取订单”，在同步任务页查看，随后在订单页查找该店铺订单。
6. 在Woo后台查看对应源订单。管理员为`haiduo_admin`，密码在本机`.woo.env`的`WOO_ADMIN_PASSWORD`。这套账号与海舵账号不同。

订单SKU需要在当前企业存在或建立商品映射。更改同步仓库和汇率只影响后续新单。不要为解决连接失败随意更换加密主密钥。

Woo种子订单默认待付款。真实付款与承运商未接入；海舵发货不会回写Woo。因此两个系统的履约状态可以不同，需要按业务规则核对。

仓库根目录的以下脚本是**会修改本地测试数据的验收工具**，不是普通查询。仅希望演练模拟付款、Webhook和利润闭环时运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File infra/verify-woocommerce-fulfillment.ps1
```

它会注册测试回调、模拟付款状态、预占并发货、录入费用和人工确认。不可对真实店铺照搬执行。详细Webhook/自动队列验收见[Woo接入说明](WOOCOMMERCE_INTEGRATION.md)。

## 8. 物流、看板与数据口径

练习：进入物流，用刚填写的运单号找记录，打开查看物流轨迹，选运输中并添加模拟事件；核对MOCK来源和版本。再模拟已签收后，该运单成为终态，旧事件不会覆盖它。此操作只改本地模拟轨迹，不通知真实承运商。

回经营总览，先选最近7天、清空店铺筛选并刷新，再填刚使用的店铺名称查询。若结果为空，检查订单创建时间和店铺名称；不要把旧测试订单是否落入时间范围作为功能故障依据。

物流页面显示海舵运单。模拟物流轨迹应保留MOCK标记；没有真实承运商连接时，不应把模拟签收当作真实送达。

看板默认人民币统计，可选最近7/30/90天及店铺。日期筛选可能排除旧演示订单，先检查时间范围。以页面展示的统计口径为准：低库存是当前库存，金额按快照计算，部分成本缺失订单会排除并提示。时间以UTC存储，页面按浏览器时区展示，趋势按UTC日期分组，午夜附近可能与本地日历不同。

订单详情中履约、支付、退款分开显示；`SHIPPED`不等于`PAID`，退款也不会自动成为仓库退货入库。

## 9. AI助手

首次体验先看顶部模式。DISABLED时可暂时跳过本节，无需为完成手册立即购买API。FIXED_DEMO时，填标题“发货约定”、正文“本店订单审核后48小时内发货，缺货需联系运营确认。”，点击导入。输入“订单多久发货？”并检索，核对来源标题。之后选择商品，填写文案要求再生成草稿，人工核对；系统不会自动发布。

进入页面先看顶部模式：

| 模式 | 含义 |
|---|---|
| DISABLED | 未启用模型，相关按钮禁用，属于正常配置状态 |
| FIXED_DEMO | 固定演示，不调用真实模型，不能宣称真实AI效果 |
| 其他已配置模型状态 | 是否真正联调成功需查看配置及实测证据 |

启用后，在“资料标题”和“知识库正文”粘贴文本或Markdown，点击“导入知识库”；正文上限12000字符。输入问题后“检索并回答”，核对来源标题与片段，资料不足时补充资料而不是把答案当作事实。问题上限4000字符。

文案区域选择商品SKU，点击“生成待审核草稿”；可在问题/说明输入区填写生成要求。结果为待人工审核内容，不会自动发布到店铺。知识库属于当前企业，不用于存放密码或令牌。索引维护由管理员按页面权限操作。

管理员若要启用演示或真实模型，参照[阶段三说明](PHASE_THREE_REPORT.md)配置并重建/重启服务；普通使用者无需自行改环境变量。真实调用需要模型凭据及费用授权。

## 10. PWA、手机和离线

手机使用抽屉导航；较宽的表格可横向滚动。浏览器支持且满足安装条件时，可通过地址栏安装按钮或浏览器“安装应用/添加到主屏幕”进入，名称和菜单因浏览器而异。

PWA只缓存静态应用资源，不缓存业务API和客户数据。离线时出现提示，订单和库存写入必须恢复网络后由你重新操作，不会自动补交。安装到桌面不代表可以离线做库存。

## 11. 常见问题

| 现象 | 处理步骤 |
|---|---|
| 8088打不开 | 检查Docker已启动；执行Compose ps，查看web/api是否正常；不要同时占用同一端口 |
| 登录失败 | 确认账号、首次初始化密码和demo环境；重启或改.env不会重置旧账号 |
| 登录后仍未选企业 | 在企业选择入口选择成员关系中的企业，再刷新页面 |
| 无权限/403 | 检查当前角色，先用管理员学习；不要关闭鉴权绕过 |
| 对象不存在/404 | 核对企业和对象ID；跨企业访问受限制是正常行为 |
| CSV导入失败 | 检查表头、店铺名、SKU、UTF-8、数量、整单金额一致性及所选仓库 |
| 预占失败 | 检查订单是否NEW、是否需人工核对、订单仓库每个SKU的可用库存 |
| 发货按钮不可用 | 先完成预占；已发货/取消或需核对订单不能正常继续发货 |
| 费用重复录入后没累加 | 同类别覆盖保存；核对账单合计后填写 |
| 398与预期不同 | 检查数量、采购成本快照、100USD收入、7.2汇率、50/72两项费用及币种 |
| 不能确认实际贡献 | 检查已付款、已发货、无退款和两类费用记录；CSV UNKNOWN不能冒充PAID |
| Woo同步没有订单 | 看同步任务、源店铺是否有可查询订单、SKU映射；不要仅凭QUEUED/COMPLETED判断成功 |
| AI按钮禁用 | 查看DISABLED提示，配置未启用时不是页面故障 |
| 修改源码页面没变化 | 容器版需要重新构建镜像；刷新浏览器，必要时检查PWA更新状态 |
| PowerShell禁止脚本 | 对本项目可信脚本使用本文的单次进程命令，不必修改全局执行策略 |

查看核心API日志：

```powershell
docker compose --env-file .env -f infra/compose.yml logs --tail 100 api
```

不要公开整个`.env`、凭据文件、备份或含客户资料的日志。故障反馈应提供操作步骤、时间、页面错误和脱敏日志。
